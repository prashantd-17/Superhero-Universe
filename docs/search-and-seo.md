# Search visibility and deployment

These changes make the site **crawlable and correctly described**. They do not
promise a position in Google, immediate indexing, or rankings for every Marvel,
DC, comics or superhero query. Broad publisher names compete with official sites
and established reference sources. Useful, original guides and specific searches
(such as a show's cast or a character's background) are more realistic targets.

## Implemented

- Absolute canonical and Open Graph URLs, defaulting to the owner-confirmed
  `https://superhero-universe.onrender.com` address. `SITE_URL` can override it for
  a future custom domain. No build-time localhost canonicals.
- Optional `GOOGLE_SITE_VERIFICATION` support for Search Console HTML-tag verification.
  This renders the supplied public verification value; it does not verify ownership by itself.
- One current title, description, canonical and set of social metadata, including
  after client-side navigation. Duplicate/stale tags are removed.
- A WebSite/Organization graph connecting **The Superhero Universe**, its short
  name, and **@thesuperhero_universe** to the real Instagram profile. The Instagram
  handle is not incorrectly represented as a verified Twitter account.
- Per-title Movie/TVSeries structured data, a default 1200×630 share image, and
  safe JSON-LD serialization. No invented ratings, reviews or awards.
- Server-rendered character profiles, products, movies, TV series and publisher
  guides. Character data comes from the bundled snapshot on the server and is
  transferred to the browser; SSR never waits for an external character API.
- `/universes/marvel` and `/universes/dc`: linked, substantive publisher guides,
  rather than keyword-only pages. `/series` makes television easy to find.
- Crawlable pagination links and a generated **`/sitemap.xml`** containing every
  known title, character, screen portrayal and top-level guide.
- Real HTTP 404 responses and `noindex` for nonexistent pages. Internal search and
  filtered archive views use `noindex, follow`; unfiltered paginated archives use
  their own canonical URLs.
- Origin-aware **`/robots.txt`** with the real sitemap location. Local and Arena
  preview origins are deliberately `noindex` and disallowed to crawlers.

## Deploy the Node application

Use a Node web service, not static hosting of `dist/superhero-universe/browser`:

```bash
npm ci
npm run build
node dist/superhero-universe/server/server.mjs
```

In the hosting provider's environment settings, configure:

```text
SITE_URL=https://superhero-universe.onrender.com
NG_ALLOWED_HOSTS=superhero-universe.onrender.com
```

These are the settings for the owner's existing Render web service. `SITE_URL`
must be an origin without a path, query or credentials. It selects one canonical
hostname when several aliases exist; without it the updated code already defaults
to the confirmed Render URL. Without an explicit `NG_ALLOWED_HOSTS`, the code
allows that production host, localhost and Arena previews (not every hostname).
A reverse proxy must preserve the public Host or X-Forwarded-Host and the correct
X-Forwarded-Proto header. Configure any legitimate aliases explicitly when needed.

Never set the production canonical domain to localhost or an Arena preview URL.
Use your hosting provider to redirect alternate domains and HTTP to your preferred
HTTPS domain. The application does not invent a domain or modify DNS.

All indexable pages are rendered on request. Static CSS, JavaScript and images
remain cacheable. The `public/robots.txt` and `public/sitemap.xml` files are safe
static fallbacks and are **excluded from application assets**: both live endpoints
are generated by `src/server/seo.ts`, including in the Angular dev server. This
prevents Vite/static middleware from shadowing the generated sitemap.

## Google Search Console checklist (owner action)

1. Open [Google Search Console](https://search.google.com/search-console), choose
   **Add property → URL prefix**, and enter **`https://superhero-universe.onrender.com/`**.
   Do not attempt to verify the parent `onrender.com` domain; its DNS belongs to Render.
   Choose **HTML tag** and copy only the `content` value into the Render environment
   variable `GOOGLE_SITE_VERIFICATION`. This value is public, not a Google password
   or OAuth/API credential. Publish/redeploy the updated code and then click Verify.
   Alternatively, place Google's provided verification HTML file in `public/` and
   redeploy it. Keep the verification method in place after verification succeeds.
2. Open `https://superhero-universe.onrender.com/robots.txt`. It should allow the public
   site and declare its absolute sitemap URL, not `Disallow: /`.
3. Open `https://superhero-universe.onrender.com/sitemap.xml`. It should contain the actual domain and the full catalog,
   not deployment placeholders or a short manually maintained list.
4. Submit `sitemap.xml` in the Sitemaps section of that URL-prefix property. Inspect the homepage, a character page,
   a series page and a publisher guide with URL Inspection; request indexing if
   appropriate. Inspect the **public** site, not the development preview.
5. Check Page Indexing and Crawl Stats after Google processes the site. A sitemap
   is a discovery aid, not an indexing or ranking guarantee.
6. Link to the public site from the community's Instagram bio and other legitimate
   owned profiles. Publish useful, original comic guides and keep references and
   release information current. Avoid keyword stuffing, bought links and copied
   articles.

- The homepage is reachable, but its title/content still match the older build.
- The live `/robots.txt` allows crawling, but contains only a commented example sitemap declaration.

- The live `/series` path returned `Not Found`; the new TV archive is not present there yet.

The local fixes and domain configuration have **not** been deployed to Render.
This coding session is closed to remote GitHub changes, so publish the saved changes
from a new coding session and deploy that updated commit before expecting the live
endpoints to change. Setting environment variables alone cannot fix the old static sitemap.

This session did not access the owner's Search Console account, submit a sitemap to
Google, modify Render settings, change DNS, or verify Google indexing/rankings.

## Checks

```bash
npm run test:server
npm run test:ci                 # Chrome/Chromium; CHROME_BIN can specify its location
npx playwright install chromium
npm run test:browser            # Starts/reuses the local Angular server
npm run build
```

Set `PLAYWRIGHT_BASE_URL` to use an already running app, and optionally
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to use an existing Chromium installation.
The browser tests intentionally block external hosts so UI/overflow checks are
repeatable. Verify real poster downloads and actual Core Web Vitals separately
in the deployment environment.
